# Требования

Статусы: `Proposed`, `Planned`, `In Progress`, `Blocked`, `Review`, `Done`, `Deferred`, `Rejected`. Приоритеты: `P0` — обязательно для целевого релиза; `P1` — важно; `P2` — уточнить/можно отложить. Все требования к платформе остаются предварительными до исследования официальной документации VK Mini Apps.

| ID | Категория | Описание и обоснование | Приоритет | Критерии приёмки | Статус |
|---|---|---|---|---|---|
| FR-001 | FR | Игра должна поддерживать партию с проверкой победы/ничьей. Это ядро продукта. | P0 | Победа и ничья корректно определяются для доступных размеров. | Done |
| FR-002 | FR | Компьютер должен делать ходы на всех доступных размерах. | P0 | AI выбирает допустимый ход; для 3×3 используется minimax, для больших досок — эвристический поиск. | Done |
| FR-003 | FR | Игрок должен выбирать easy, medium или hard. | P1 | Выбор применяется к следующей партии и сохраняется в её результате. | Done |
| FR-004 | FR | Игрок должен выбирать поле 3×3, 4×4 или 5×5. | P1 | Отрисовка, правила и AI согласованы с размером поля. | Done |
| FR-005 | FR | Приложение должно показывать таймер партии и времени хода. | P1 | Таймеры запускаются/останавливаются вместе с состоянием партии. | Done |
| UI-001 | UI | Основной интерфейс должен предоставлять игру, статистику и информацию о проекте. | P1 | Вкладки доступны и содержат соответствующие панели. | Done |
| DATA-001 | DATA | Локально сохранять историю завершённых партий и вычислять личную статистику. | P1 | Данные переживают перезагрузку в том же браузере и валидируются при загрузке. | Done |
| DATA-002 | DATA | Будущие пользовательские данные должны быть доступны между сеансами/устройствами, если это поддерживает выбранная архитектура Mini Apps. | P1 | Пользователь видит согласованные данные после входа на другом устройстве; схема и политика хранения документированы. | Proposed |
| VK-001 | VK | Игра должна запускаться и корректно взаимодействовать с окружением VK Mini Apps. | P0 | Сценарии жизненного цикла и запуск проходят в официально поддерживаемом тестовом окружении. | Proposed |
| VK-002 | VK | Идентифицировать пользователя с использованием одобренного механизма Mini Apps. | P0 | Успешный вход, отказ и истечение/ошибка сессии обработаны; серверная проверка определена. | Proposed |
| NET-001 | NET | Два пользователя должны играть одну сетевую партию с согласованным состоянием. | P0 | Валидные ходы синхронизируются; недопустимые/повторные ходы отклоняются. | Proposed |
| NET-002 | NET | Сетевой матч должен корректно обрабатывать отмену, разрыв и повторное подключение/завершение. | P1 | Игрок получает ясный итог; результат не записывается дважды. | Proposed |
| DATA-003 | DATA | Сохранять результаты и предоставлять персональную статистику/рейтинг через согласованную модель. | P1 | Доступ к данным изолирован по пользователю; правила рейтинга повторяемы и серверно проверяемы. | Proposed |
| ADS-001 | ADS | Монетизация должна использовать разрешённый для VK Mini Apps рекламный механизм. | P1 | Показ соответствует официальным условиям и UX; отказ/ошибка рекламы не блокируют игру. | Proposed |
| NFR-001 | NFR | Платформенные интеграции должны быть отделены от игрового ядра. | P1 | Правила партии можно использовать без SDK Mini Apps; платформенные вызовы проходят через адаптер. | Planned |
| NFR-002 | NFR | Ошибки платформы и сети должны обрабатываться без потери целостности локальной партии. | P1 | Ошибка интеграции не приводит к невалидному состоянию или необработанному сбою. | Planned |
| NFR-003 | NFR | Не хранить секреты и доверенные credentials в публичном клиентском коде. | P0 | Проверка релизного набора не находит ключей; серверная проверка определена. | Planned |
| NFR-004 | NFR | Проект должен соответствовать актуальным правилам Mini Apps и минимизировать персональные данные. | P0 | Для платформенных требований указаны актуальные официальные источники и обоснование. | Proposed |
