# Требования

Статусы: `Proposed`, `Planned`, `In Progress`, `Blocked`, `Review`, `Done`, `Deferred`, `Rejected`. Приоритеты: `P0` — обязательно для целевого релиза; `P1` — важно; `P2` — уточнить/можно отложить. Все требования к платформе остаются предварительными до исследования официальной документации VK Mini Apps.

| ID | Категория | Описание и обоснование | Приоритет | Критерии приёмки | Статус |
|---|---|---|---|---|---|
| FR-001 | FR | Игра должна поддерживать партию с проверкой победы/ничьей. Это ядро продукта. | P0 | Победа и ничья корректно определяются для доступных размеров. | Done |
| FR-002 | FR | Компьютер должен делать ходы на всех доступных размерах. | P0 | AI выбирает допустимый ход; для 3×3 используется minimax, для больших досок — эвристический поиск. | Done |
| FR-003 | FR | Игрок должен выбирать easy, medium или hard. | P1 | Выбор применяется к следующей партии и сохраняется в её результате. | Done |
| FR-004 | FR | Игрок должен выбирать поле 3×3, 4×4 или 5×5. | P1 | Отрисовка, правила и AI согласованы с размером поля. | Done |
| FR-005 | FR | Приложение должно показывать таймер партии и времени хода. | P1 | Таймеры запускаются/останавливаются вместе с состоянием партии. | Done |
| UI-001 | UI | Основной интерфейс должен предоставлять игру, статистику и информацию о проекте. | P1 | Вкладки доступны и содержат соответствующие панели. | Done |
| UI-002 | UI | В версии игры для VK Mini Apps должна быть отдельная кнопка перехода на сообщество PCP Games вместо кнопки Дзена. Канал Дзена не удалять и оставить для внешнего продвижения. | P1 | Кнопка отображается отдельно, ведёт на подтверждённый URL сообщества; кнопки Дзена нет в Mini Apps-варианте, ссылка на сам канал сохранена вне этого CTA. | Planned |
| VK-003 | VK | Подготовить официальную страницу сообщества PCP Games и связать её с приложением VK Mini Apps. | P1 | Название, описание, материалы и фактический URL подтверждены владельцем; переход соответствует актуальным правилам Mini Apps. | Planned |
| DATA-001 | DATA | Локально сохранять историю завершённых партий и вычислять личную статистику. | P1 | При доступном localStorage данные переживают перезагрузку в том же browser profile и валидируются при загрузке; при недоступном storage UI продолжает работать в volatile fallback без обещания персистентности. | Done |
| DATA-002 | DATA | Будущие пользовательские данные должны быть доступны между сеансами/устройствами, если это поддерживает выбранная архитектура Mini Apps. | P1 | Пользователь видит согласованные данные после входа на другом устройстве; схема и политика хранения документированы. | Proposed |
| DATA-004 | DATA | Статистика должна агрегировать сыгранные партии, исходы, сложность и размер поля; лучшее время считать по явно определённому режиму. | P1 | Группировка и определения показателей документированы, значения совпадают с валидными match records. | Done |
| DATA-005 | DATA | Разделять гостевые данные и данные авторизованного пользователя, не связывать локальный профиль с VK-аккаунтом без подтверждённой идентификации и согласованной привязки. | P0 | Два пользователя на одном устройстве не видят чужую статистику; правила связывания/отвязки и guest flow проверены. | Proposed |
| DATA-006 | DATA | При наличии выбранной поддерживаемой архитектуры синхронизировать согласованные результаты между сеансами и устройствами. | P1 | Данные восстанавливаются после переустановки/смены устройства; offline/error поведение описано. | Proposed |
| DATA-007 | DATA | Глобальный рейтинг должен иметь явные правила, проверку достоверности и защиту от подмены результатов. | P1 | Клиент не может самостоятельно повысить рейтинг; серверная валидация и правила одинаково применяются к участникам. | Proposed |
| DATA-008 | DATA | Миграция существующей локальной статистики должна быть необязательной, идемпотентной и не удалять исходные данные без отдельного решения. | P0 | При отказе/ошибке оригинальный localStorage остаётся доступен; повтор миграции не дублирует матчи. | Proposed |
| VK-001 | VK | Игра должна запускаться и корректно взаимодействовать с окружением VK Mini Apps. | P0 | Сценарии жизненного цикла и запуск проходят в официально поддерживаемом тестовом окружении. | Proposed |
| VK-002 | VK | Идентифицировать пользователя с использованием одобренного механизма Mini Apps. | P0 | Успешный вход, отказ и истечение/ошибка сессии обработаны; серверная проверка определена. | Proposed |
| NET-001 | NET | Два пользователя должны играть одну сетевую партию с согласованным состоянием. | P0 | Валидные ходы синхронизируются; недопустимые/повторные ходы отклоняются. | Proposed |
| NET-002 | NET | Сетевой матч должен корректно обрабатывать отмену, разрыв и повторное подключение/завершение. | P1 | Игрок получает ясный итог; результат не записывается дважды. | Proposed |
| NET-003 | NET | Онлайн-режим должен автоматически подбирать случайного ожидающего пользователя VK Mini Apps после нажатия «Играть онлайн» и запускать парный матч без предварительной договорённости. | P0 | Очередь допускает отмену и несколько одновременных пользователей; каждый пользователь находится максимум в одной активной очереди/паре; match ID уникален; стороны автоматически получают X/O и видят друг друга; матч стартует после подтверждённой готовности. Приглашения друзей, коды комнат и ручное создание комнат не являются обязательным функционалом. | Proposed |
| NET-004 | NET | Ходы и исход матча должны проверяться авторитетной моделью, определённой архитектурным решением. | P0 | Серверная сторона или иной обоснованный доверенный компонент отклоняет неверного игрока, ход не по очереди, занятую клетку, ход после окончания, повторную/дублирующую команду и подменённый исход; запись результата идемпотентна. | Proposed |
| NET-005 | NET | Игровая сессия должна быть связана с пользователем через подтверждённые данные VK Mini Apps, прошедшие требуемую проверку. | P0 | Клиент не может произвольно выдать себя за другой VK ID; проверка выполняется доверенным способом согласно актуальной официальной схеме; секреты не находятся в клиенте. | Proposed |
| NET-006 | NET | Участники матча должны видеть проверенное имя и аватар соперника с определённым поведением при недоступности профиля. | P1 | Идентификаторы и отображаемые данные относятся к фактическим участникам; отказ загрузки не блокирует допустимый матч и не раскрывает лишние поля профиля. | Proposed |
| DATA-003 | DATA | Сохранять результаты и предоставлять персональную статистику/рейтинг через согласованную модель. | P1 | Доступ к данным изолирован по пользователю; правила рейтинга повторяемы и серверно проверяемы. | Proposed |
| ADS-001 | ADS | Монетизация должна использовать разрешённый для VK Mini Apps рекламный механизм. | P1 | Показ соответствует официальным условиям и UX; отказ/ошибка рекламы не блокируют игру. | Proposed |
| NFR-001 | NFR | Платформенные интеграции должны быть отделены от игрового ядра. | P1 | Правила партии можно использовать без SDK Mini Apps; платформенные вызовы проходят через адаптер. | Planned |
| NFR-002 | NFR | Ошибки платформы и сети должны обрабатываться без потери целостности локальной партии. | P1 | Ошибка интеграции не приводит к невалидному состоянию или необработанному сбою. | Planned |
| NFR-003 | NFR | Не хранить секреты и доверенные credentials в публичном клиентском коде. | P0 | Проверка релизного набора не находит ключей; серверная проверка определена. | Planned |
| NFR-004 | NFR | Проект должен соответствовать актуальным правилам Mini Apps и минимизировать персональные данные. | P0 | Для платформенных требований указаны актуальные официальные источники и обоснование. | Proposed |
| NFR-005 | NFR | Локальный провайдер статистики должен оставаться универсальным и не зависеть от SDK, если аудит не выявляет платформенной зависимости. | P1 | Существующая локальная история работает независимо от VK Bridge; платформенные слои добавляются адаптерами. | Planned |
| NFR-006 | NFR | Ссылки на сообщество должны открываться безопасно и предсказуемо в целевых mobile и desktop клиентах Mini Apps. | P1 | Точное назначение URL, пользовательский жест, поведение клиента и fallback проверены на поддерживаемых окружениях. | Proposed |
