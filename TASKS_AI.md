## 1. Текущее состояние проекта
- **Базовая игра:** полностью готова и функциональна в браузере (HTML5, CSS3, ES6-модули без сборщиков).
- **Платформенная интеграция:** в игровом коде пока **нет** вызовов `@vkontakte/vk-bridge`, авторизации VK ID и рекламы.
- **Сетевой прототип:** в каталоге `webrtc-prototype/` имеется рабочий прототип на Cloudflare Worker / Durable Objects (SQLite), реализующий очередь случайного подбора и сигнализацию WebRTC, однако ходы и исходы матчей передаются P2P через DataChannel без серверной валидации.
- **Статистика:** работает локально в `localStorage` без привязки к VK ID. Глобальный лидерборд в UI пока представлен визуальной заглушкой.

## 5. Последующие этапы разработки (Дорожная карта)

- **PH-003. Базовая интеграция VK Mini Apps:** запуск приложения внутри фрейма VK, обработка жизненного цикла, fallback при автономном запуске в обычном браузере.
- **PH-004. Платформенная идентификация:** безопасная авторизация, передача данных запуска на сервер, минимизация собираемых персональных данных (NFR-003, NFR-004).
- **PH-005. Быстрый случайный онлайн-мультиплеер:** реализация утверждённого транспорта, автостарт матча по одной кнопке, видимый поиск, защита от повторных/невалидных ходов, обработка разрыва соединения и reconnect.
- **PH-006. Данные, синхронизация и лидерборд:** сохранение локальной истории матчей в `localStorage`; синхронизация профиля в `VKWebAppStorage` (до 4 КБ); ведение глобального рейтинга на сервере с защитой от накрутки.
- **PH-007. Рекламная монетизация:** интеграция межстраничных и rewarded объявлений через VK Bridge с безопасным UX (ошибка рекламы не блокирует игру).
- **PH-008. Адаптация интерфейса и окружения:** тестирование верстки на десктопе, Android и iOS клиентах ВКонтакте, экранах с разным соотношением сторон.

## 6. Известные проблемы и технические ограничения
1. **Текущий прототип webrtc-prototype:** ходы идут P2P через DataChannel без серверной валидации, что уязвимо к искажению ходов. Требуется поэтапная замена на WSS-архитектуру с Match DO. Сам прототип сохраняется в каталоге `webrtc-prototype/` без изменений до завершения миграции.
2. **Лимит VK Storage:** платформенное хранилище ограничено 4096 байтами на ключ. Используется только для краткой агрегированной сводки, а полная история и рейтинг ведутся в Cloudflare D1.
3. **Смешение пользователей на одном ПК:** локальная статистика в `localStorage` должна быть изолирована по ключам `tictactoe.vk_{vk_user_id}.stats.v1`.

## 7. Важные открытые технические вопросы
1. **Регистрация в кабинете разработчика VK:** получение реального `App ID` и `Client Secret` для настройки серверной проверки HMAC-SHA256 подписи параметров запуска и запросов к VK API (`users.get`).
2. **Параметры сообщества PCP Games:** числовой `group_id` для настройки нативного вызова `VKWebAppJoinGroup`.
3. **Калибровка таймеров:** уточнение длительности таймера хода (предварительно 30 сек) и grace period восстановления соединения (предварительно 15 сек) по результатам тестирования.

## 8. Принятые решения, которые нельзя забывать

- **DEC-001 (Целевая платформа):** только VK Mini Apps. VK Play и Яндекс Игры исключены из проекта.
- **DEC-002, DEC-009 (Сетевая архитектура онлайна):** **Server-Authoritative WebSocket** на Cloudflare Workers + Durable Objects + Cloudflare D1.
  - *Worker:* входной шлюз, проверка подписи HMAC-SHA256, проверка `vk_app_id` и выдача короткоживущего токена сессии.
  - *Matchmaker DO:* единая очередь случайного подбора FIFO (для MVP).
  - *Match DO:* отдельный сессионный инстанс на каждый матч (доска, ходы, таймеры, reconnect).
  - *Cloudflare D1:* постоянная реляционная БД для профилей, результатов матчей и глобального рейтинга.
- **DEC-005 (Сохранение локальной статистики):** существующий провайдер в `player-stats.js` сохраняется как универсальная основа для локальной игры/guest.
- **DEC-008 (Концепция онлайна):** случайный подбор по одной кнопке без ручных комнат, кодов, ссылок и обязательной дружбы.
- **Безопасность авторизации и профилей:**
  - Клиент получает токен сессии через POST `/api/auth` и подключается по WSS без передачи сырых параметров запуска в URL;
  - Сервер не доверяет имени и аватару от клиента; профиль верифицируется через серверный вызов VK API или кэш D1;
  - Защита от параллельных сессий одного VK ID (закрытие старого сокета);
  - Идемпотентность ходов по номеру `seq` и валидация принадлежности к `matchId`.
- **Сообщество:** ссылка на Дзен убирается только из сборки/версии для VK Mini Apps; внешний канал Дзена сохраняется.
- **Игровое ядро:** чистая логика правил в `game-logic.js` отделена от платформенного и сетевого кода.
