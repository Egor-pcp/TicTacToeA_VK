## 1. Текущее состояние проекта
- **Базовая игра:** полностью готова и функциональна в браузере (HTML5, CSS3, ES6-модули без сборщиков).
- **Сетевой онлайн-мультиплеер (Server-Authoritative WSS):**
  - Бэкенд на Cloudflare Workers + Durable Objects (`Matchmaker`, `Match`) + D1 (`users`, `match_history`, `leaderboards`) полностью реализован в рамках Блока 1 (Development Mode).
  - Клиентский адаптер `OnlineServerClient.js` подключен к игре: авторизация, поиск соперника, авторитетная валидация ходов, синхронизация доски, таймеры, автовосстановление сессии при дисконнекте.
  - Реализован обратный отсчёт (15..0 сек) при отключении соперника и техническое поражение при неявке в едином информационном поле `#game-status`.
  - Разделение окружений: локальный `Development Mode` с переключателем `dev_user_1` / `dev_user_2` и боевой `VK Mini Apps Mode`.
- **Платформенная интеграция VK:** реализована архитектура платформенных адаптеров `platform-adapter.js` (`MockPlatformAdapter` в Dev Mode и `VkBridgeAdapter` в VK Mini Apps Mode). В рамках VK-003-007.1 и VK-003-007.2 реализована полная изоляция и защита Production: `MockPlatformAdapter` разрешён исключительно в доверенном локальном окружении (`localhost`, `127.0.0.1`, `::1`, `0.0.0.0`, `file://`), на боевых хостах параметры URL (`?dev_user=...`, `?mode=dev`) и попытки `forceMode: "development"` игнорируются, возвращая `VkBridgeAdapter`. Исправлен кулдаун рекламы (время обновляется только при успешном показе `response?.result === true`), подтверждены контракты VK Bridge. Пройдено 98 автоматических тестов (100% pass).
- **Статистика и рейтинг:** реализована изоляция персональной статистики в `localStorage` по ключам `tictactoe.vk_{user_id}.stats.v1`, серверное сохранение результатов матчей в Cloudflare D1 (`users`, `match_history`, `leaderboards`), API `GET /api/leaderboard` с детерминированной сортировкой и отображение топ-10 глобального рейтинга во вкладке «Рейтинг» с состояниями загрузки, ошибки и выделением топ-3 мест. Пройдено 69 автоматических тестов (100% pass).

### UI-003 — Поведение интерфейса во время поиска соперника
Замеченные проблемы:
1. Во время ожидания подбора соперника не обновляется таймер ожидания.
2. Пока идёт поиск соперника, не запускается предусмотренное интерфейсом поведение «пока сыграй сам с собой» (требуется уточнить и реализовать согласованное поведение).

**Принятое решение:**
- Пока не исправлять. Не изменять алгоритм поиска, очередь Matchmaker и серверную логику в рамках документационной задачи.
- На следующем этапе UX-доработки отдельно определить:
  - должен ли игрок иметь возможность играть против ИИ, пока сервер ищет соперника;
  - как отображать состояние поиска и прошедшее время;
  - как переключаться на найденного соперника без потери состояния интерфейса.

**Статус:** ОТЛОЖЕНО. Требует отдельной постановки задачи.

## 8. Известные проблемы и технические ограничения
1. **Текущий прототип webrtc-prototype:** ходы идут P2P через DataChannel без серверной валидации, что уязвимо к искажению ходов. Заменяется на WSS-архитектуру с Match DO. Сам прототип сохраняется в каталоге `webrtc-prototype/` без изменений до завершения миграции.
2. **Лимит VK Storage:** платформенное хранилище ограничено 4096 байтами на ключ. Используется только для краткой агрегированной сводки, а полная история и рейтинг ведутся в Cloudflare D1.
3. **Смешение пользователей на одном ПК:** локальная статистика в `localStorage` должна быть изолирована по ключам `tictactoe.vk_{vk_user_id}.stats.v1`.

## 9. Принятые решения, которые нельзя забывать

- **DEC-001 (Целевая платформа):** только VK Mini Apps. VK Play и Яндекс Игры исключены из проекта.
- **DEC-002, DEC-009 (Сетевая архитектура онлайна):** **Server-Authoritative WebSocket** на Cloudflare Workers + Durable Objects + Cloudflare D1.
  - *Worker:* входной шлюз, проверка подписи HMAC-SHA256, проверка `vk_app_id` и выдача короткоживущего токена сессии.
  - *Matchmaker DO:* единая очередь случайного подбора FIFO (для MVP).
  - *Match DO:* отдельный сессионный инстанс на каждый матч (доска, ходы, таймеры, reconnect).
  - *Cloudflare D1:* постоянная реляционная БД для профилей, результатов матчей и глобального рейтинга.
- **DEC-005 (Сохранение локальной статистики):** существующий провайдер в `player-stats.js` сохраняется как универсальная основа для локальной игры/guest.
- **DEC-008 (Концепция онлайна):** случайный подбор по одной кнопке без ручных комнат, кодов, ссылок и обязательной дружбы.
- **DEC-010 (Стратегия разработки в двух режимах):**
  - Мы не выходим в реальную платформу VK после каждого модуля;
  - Продукт полностью разрабатывается локально в `Development Mode` (мок-авторизация, мок VK Bridge, тестирование онлайна на 2 окна);
  - Единая кодовая база с адаптерами `IPlatformAdapter`;
  - Комплексные испытания в реальной среде VK Mini Apps вынесены на отдельный этап перед модерацией.
- **UI-002 (Единое информационное поле игровых событий):**
  - Элемент `#game-status` в нижней части интерфейса является основным и единым местом отображения текстовой информации о происходящем в игре (очередь хода, поиск, отмена, дисконнект/отсчёт, reconnect, результат, статус соединения).
  - Запрещено создавать новые панели, модальные окна и всплывающие уведомления без прямого согласования с владельцем.
  - Новые игровые события интегрируются строго через существующий механизм `#game-status`. Обычный вызов `updateInterface()` не должен перетирать критичные сообщения о статусе матча.
- **Безопасность авторизации и профилей:**
  - Клиент получает токен сессии через POST `/api/auth` и подключается по WSS без передачи сырых параметров запуска в URL;
  - Сервер не доверяет имени и аватару от клиента; профиль верифицируется через серверный вызов VK API или кэш D1;
  - Защита от параллельных сессий одного VK ID (закрытие старого сокета);
  - Идемпотентность ходов по номеру `seq` и валидация принадлежности к `matchId`.
- **Сообщество:** ссылка на Дзен убирается только из сборки/версии для VK Mini Apps; внешний канал Дзена сохраняется.
- **Игровое ядро:** чистая логика правил в `game-logic.js` отделена от платформенного и сетевого кода.
