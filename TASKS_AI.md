## 1. Паспорт проекта

- **Название:** TicTacToeA_VK.
- **Назначение:** адаптация существующей браузерной игры «Крестики-нолики» для **VK Mini Apps**.
- **Репозиторий:** [Egor-pcp/TicTacToeA_VK](https://github.com/Egor-pcp/TicTacToeA_VK), ветка `main`.
- **Целевая платформа:** только VK Mini Apps. VK Play и Яндекс Игры не входят в scope.
- **Технологии:** основное приложение — HTML, CSS, нативные JavaScript modules; сетевой эксперимент — WebRTC/WebSocket, Cloudflare Worker и Durable Objects.
- **Область работы:** сохранить работающую базовую игру; отдельно планировать VK интеграцию, случайный multiplayer, данные, community link, монетизацию, тестирование и публикацию.

## 2. Что уже реализовано

- Браузерная игра с полями 3×3, 4×4 и 5×5; режим против компьютера; уровни easy/medium/hard.
- AI: minimax для 3×3 и эвристический поиск для больших полей; таймер партии и хода.
- Локальная статистика в `player-stats.js`: история завершённых матчей и агрегаты хранятся в `localStorage`, с volatile fallback при его недоступности.
- Существует экспериментальный online P2P-путь: WebSocket сигнализация и подбор пары через Worker/Durable Object, затем WebRTC DataChannel для peer traffic.
- Проектная документация описывает факт и план раздельно; первый snapshot опубликован в GitHub. Последний commit указан выше.

## 3. Что установлено аудитом

- В game code не найдено Yandex Games SDK (`YaGames`, `ysdk`) или VK Bridge/Mini Apps SDK. Идентификация, platform storage и VK integration ещё не реализованы.
- Статистика универсальна и локальна: `tictactoe.player-profile.v1` и `tictactoe.player-stats.v1`. Локальный display ID/random identity key — не VK identity. Записи матчей не связаны с ID профиля; разные пользователи на одном browser origin сейчас не изолированы.
- История хранит ID, дату, результат, winner, mode, board size, difficulty и duration. Агрегируются партии, победы/поражения/ничьи по параметрам; UI выводит число партий и лучшее время. Лучшее время учитывает победу X против компьютера. Таблица рейтинга — placeholder; backend leaderboard не найден.
- В WebRTC-прототипе Worker маршрутизирует `/ws` в один Durable Object; DO содержит FIFO очередь и временные пары, умеет отмену, ready handshake, heartbeat и очистку stale состояний. DO сигнализирует SDP/ICE, а игровые сообщения идут по DataChannel. Нет server-authoritative состояния игры, проверки ходов/результата, VK identity, production reconnect, TURN и anti-abuse.
- Отдельного production matchmaking сервиса VK Mini Apps пока не подтверждено. Прототип не равен такому сервису. Подробные доказательства и ограничения: [ARCHITECTURE.md](./ARCHITECTURE.md), [docs/VK-MINI-APPS-RESEARCH.md](./docs/VK-MINI-APPS-RESEARCH.md), [webrtc-prototype/README.md](./webrtc-prototype/README.md).

## 4. Текущая концепция и правила

- Multiplayer: пользователь нажимает одну кнопку «Играть онлайн», автоматически попадает в очередь случайного подбора пользователей в игре; после подбора начинается матч, назначаются X/O, показываются имя и аватар.
- **Приглашения, коды комнат, ручное создание комнат, ссылки на матч и обязательная дружба не входят в обязательный сценарий.** Не возвращать их в требования или roadmap без нового решения владельца.
- Предусмотреть отмену поиска, видимый поиск, атомарные пары, единственную активную очередь/матч на игрока, проверку очередности/легальности/повтора хода, победу/поражение/ничью, разрыв и повторное подключение.
- Идентификация VK, matchmaking, серверная проверка партии и статистическое хранилище — отдельные обязанности. Авторитетность серверной логики и транспорт требуют исследования и согласования.
- WebSocket + серверное управление — предварительный кандидат для сравнения, не утверждённая архитектура. Cloudflare Worker/Durable Objects — возможный кандидат, но текущий прототип нуждается в существенном расширении и проверке лимитов/стоимости. Не писать код до решения владельца.
- Сохранить local stats provider как универсальную основу. Не связывать/мигрировать старые записи без отдельной политики; не выбирать storage/backend/leaderboard до анализа и согласования.
- Планируется отдельная кнопка PCP Games community в варианте Mini Apps вместо CTA Дзена; сообщество и URL пока неизвестны. Не придумывать URL и не удалять сам канал Дзена.

## 7. Важные правила для ИИ

- Не разрабатывать игру заново, не менять игровую логику без прямого задания и не переписывать/удалять `webrtc-prototype` без решения пользователя.
- Не смешивать VK Mini Apps с VK Play; не использовать документацию VK Play и не считать Яндекс-интеграцию существующей без факта в коде.
- Не объявлять API, backend, transport, storage, цену, лимиты или правила платформы подтверждёнными без актуального источника VK Mini Apps/провайдера.
- Не менять существенную архитектуру и не мигрировать пользовательские данные без решения владельца.
- Не помечать запланированные функции или невыполненные тесты как `Done`.
- Не делать `git add`, commit или push без прямого разрешения.
- Не устанавливать/обновлять зависимости; не удалять и не перемещать файлы без прямого задания.
- Соблюдать единые статусы: `Proposed`, `Planned`, `In Progress`, `Blocked`, `Review`, `Done`, `Deferred`, `Rejected`.
