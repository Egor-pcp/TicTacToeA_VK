# Архитектура проекта TicTacToeA_VK

Целевая платформа: **VK Mini Apps**. Данный документ описывает подтверждённую фактическую архитектуру кодовой базы и проектные ориентиры будущих слоёв интеграции.

---

## 1. Фактическая архитектура игры

### 1.1. Клиентское ядро
Приложение построено на нативных ES6 JavaScript-модулях и не требует сборки:
- **[index.html](./index.html)** — семантическая разметка трех основных экранов: вкладка «Играть» (настройки, табло, игровое поле), «Рейтинг» (сводка и таблица лидеров) и «О проекте» (информация об авторе и CTA).
- **[style.css](./style.css)** — стили, темы и адаптивная верстка под десктоп и мобильные экраны.
- **[game-logic.js](./game-logic.js)** — изолированная чистая логика правил крестиков-ноликов:
  - Определение линий победы: 3 в ряд для поля 3×3; 4 в ряд для полей 4×4 и 5×5.
  - Проверка ничьих (`isDrawPosition`).
  - Логика ИИ: минимакс с альфа-бета отсечением для доски 3×3; эвристический позиционный поиск линий для досок 4×4 и 5×5.
- **[script.js](./script.js)** — главный координатор:
  - Управление состоянием DOM, переключение вкладок (`game-view`, `stats-view`, `about-view`).
  - Таймеры партии и ходов (`createTimerState`).
  - Связывание событий завершения партии с записью в статистику.
  - Подключение и обработка онлайн-сессии через `OnlineClient`.
- **[player-stats.js](./player-stats.js)** — локальная подсистема статистики:
  - Хранилище: `localStorage` с fallback на оперативное хранилище (`volatileStorage`) при ограничениях браузера.
  - Ключи: `tictactoe.player-profile.v1` (локальный `displayId` вида `ID_DDMMhhmmss` и токен) и `tictactoe.player-stats.v1` (массив записей завершенных матчей).
  - Агрегаторы: подсчет сыгранных партий, исходов (победы/поражения/ничьи), лучшего времени победы X против ИИ по категориям сложности и размеров доски.

### 1.2. Сетевой прототип ([webrtc-prototype/](./webrtc-prototype/README.md))
В репозитории содержится работающий прототип случайного матчмейкинга:
- **Cloudflare Worker ([webrtc-prototype/src/worker.js](./webrtc-prototype/src/worker.js))**: маршрутизирует WebSocket-запросы `/ws` в Durable Object `Matchmaker`.
- **Durable Object (`Matchmaker`)**:
  - Хранит в локальной SQLite очередь ожидания (`waiting`) и пары (`matches`).
  - Реализует случайный подбор пары (FIFO), отмену поиска, подтверждение готовности (`ready`) и периодический heartbeat.
  - Выполняет функцию сигнального сервера WebRTC: ретранслирует сообщения типа `signal` (SDP-офферы, ответы и ICE-кандидаты) между спаренными клиентами.
- **Клиентский транспорт ([webrtc-prototype/public/online-client.js](./webrtc-prototype/public/online-client.js))**:
  - Устанавливает P2P-соединение через `RTCPeerConnection` (используется публичный Google STUN, TURN отсутствует).
  - Передает ходы и исходы матчей напрямую между браузерами через `RTCDataChannel`.
- **Границы возможностей прототипа**:
  - Сервер **не знает** состояния игрового поля и не валидирует ходы.
  - Нет серверной проверки исходов: результаты определяются самими клиентами.
  - Нет привязки к аккаунту VK и сессионной авторизации.

## 2. Результаты официального исследования платформы VK Mini Apps

В ходе исследования портала разработчиков ВКонтакте (dev.vk.com) и библиотеки `@vkontakte/vk-bridge` установлены подтверждённые факты:

1. **Аутентификация и проверка запуска:**
   - Клиент получает в URL параметры запуска с префиксом `vk_*` и цифровую подпись `sign`.
   - Сервер валидирует параметры: фильтрует ключи с префиксом `vk_`, сортирует по алфавиту, собирает query-строку и вычисляет HMAC-SHA256 хеш с использованием секретного ключа (`Client Secret`). Хеш кодируется в Base64URL и сверяется с `sign`.
   - **Правило безопасности:** секретный ключ приложения хранится строго на бэкенде.
2. **Отсутствие встроенного матчмейкинга:**
   - VK Mini Apps не предоставляет серверов комнат или валидации пошаговых игр. Сервер очереди, комнат и логики сессий полностью реализуется разработчиком.
3. **Хранилище платформы (`VKWebAppStorage*`):**
   - Лимит: строго до **4096 байт (4 КБ)** на значение одного ключа; до ~40 ключей на пользователя.
   - Подходит для сохранения сводных показателей и профиля, но **непригодно** для расширяющейся истории матчей.
4. **Сообщество и ссылки:**
   - `VKWebAppJoinGroup` — нативное вступление в группу ВК по `group_id` без закрытия приложения.
   - `VKWebAppOpenUrl` — открытие внешних ссылок.
   - Внешний CTA на Дзен в версии Mini Apps заменяется переходом в сообщество PCP Games ВКонтакте.
5. **Рекламные форматы:**
   - `VKWebAppCheckNativeAds` / `VKWebAppShowNativeAds` (rewarded / interstitial).
   - `VKWebAppShowBannerAd` / `VKWebAppHideBannerAd` (баннеры).

## 3. Сравнение архитектур онлайн-мультиплеера (DEC-002, DEC-009)

| Критерий | Вариант 1: WebRTC P2P DataChannel | Вариант 2: Server-Authoritative WebSocket |
|---|---|---|
| **Валидация правил** | Клиентская (риск читерства и рассинхронизации) | Серверная (сервер проверяет каждый ход, очередность и победу) |
| **Сетевая надежность** | Требует STUN/TURN; высокий риск обрыва при строгом NAT | 100% стабильность через стандартный WSS (порт 443) |
| **Фиксация результатов** | Клиенты сами сообщают исход матча | Сервер формирует доверенный результат для рейтинга |
| **Переподключение** | Сложное повторное согласование ICE-кандидатов | Простое переподключение сокета по сессионному токену |
| **Сложность бэкенда** | Сервер только ретранслирует сигналы | Сервер выполняет проверку логики партии |

*Примечание:* Выбор между доработкой прототипа на Cloudflare Durable Objects (WebSocket) и развитием WebRTC с TURN зафиксирован в [TASKS_AI.md](./TASKS_AI.md) как открытый технический вопрос для последующего согласования.

## 4. Проектируемые слои будущей интеграции

Целевая декомпозиция (проектируемое направление, не изменяющее текущую игру):
1. **Core Game Logic (`game-logic.js`):** чистые правила партии без привязки к платформе или сети.
2. **UI & View Layer (`index.html`, `script.js`):** отображение игры, таймеров, экранов и адаптация под мобильные экраны ВК.
3. **VK Bridge Adapter (будущий слой):** изоляция вызовов `@vkontakte/vk-bridge` (инициализация, banner/interstitial реклама, подписка на сообщество).
4. **Matchmaking & Game Server (будущий бэкенд):**
   - Проверка подписи запуска (`sign`) через HMAC-SHA256.
   - Очередь случайного поиска (FIFO) без ручных комнат и инвайтов.
   - Авторитетное ведение партии и дедуплицированная фиксация исходов.
5. **Storage & Leaderboard Layer:**
   - Локальный провайдер (`localStorage`) сохраняется как универсальная основа.
   - Сводные данные профиля синхронизируются через `VKWebAppStorage` (до 4 КБ).
   - Глобальный лидерборд и полная история хранятся на доверенном бэкенде.
